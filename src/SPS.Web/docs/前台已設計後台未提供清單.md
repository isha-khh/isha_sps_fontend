方法：逐頁列出 SPS.Web 29 個頁面的資料來源（`fetchXxx` 真後端或 `lib/*-data.ts` 靜態資料、表單有沒有送出邏輯），對照 AdminWeb 選單（`layouts/AdminLayout.tsx`）與後端 Controller／Entity。

## 四、會員中心尚未做的區塊

`MemberCenterContent` 只有「基本資料」「權益升級」兩個真的，其餘都顯示「即將推出」：變更密碼、Passkey 管理、公司資料、成員管理、產品相關資訊、媒合資料維護、我的最愛。後端已有 `Product`、`MemberFavorite`、`MemberDemand` 等實體，後台也有產品管理，缺的是前台會員自助維護（授權要用「依 CompanyId 限定擁有者」的獨立端點，見 `api-authorization-audit-2026-10-03.md` 未處理第 5 項）。

## 五、不算缺口的

- 首頁主視覺、各頁側欄廣告：用「橫幅管理」維護（上線後要記得上傳）。
- 公告、產業案例、影音、常見問題、頁尾連結、頁面設定（投稿、下載資源）：前後台都已接上。
- 會員比較表 `/member/compare`、網站導覽 `/sitemap`：屬於固定的說明內容，改版頻率低，目前沒有做成後台可維護的必要。
- 申請審核、委員評分：後台已有（`ExpertScoringSection`）。

## 建議的處理順序

1. **#13、#14**（前台串接現成的後台功能）：工作量最小，馬上讓媒合頁變成真資料。
2. **#9～#12**（表單收件）：做一組通用的「詢問單」資料表與後台收件匣，四五個表單共用。
3. **#8 公告附件**：範圍小。
4. **#1～#7**：每一塊都是新內容類型，先決定哪些真的要由後台維護，再一個一個做；#1／#2／#3 的欄位結構相近，可以用同一個「內容項目＋附件」模型。
