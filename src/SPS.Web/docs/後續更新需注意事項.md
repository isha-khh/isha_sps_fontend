## B. 上線時要設定／確認的環境設定

- [ ] `Bounce_Webhook__Secret`（至少 16 字元）：**只有**外部郵件伺服器會呼叫 `POST /api/Log/mail/bounce` 時才需要。沒設定時這個端點停用（回 503），不影響其他功能。設定後呼叫端要帶標頭 `X-Webhook-Secret`，兩邊密鑰一致。目前 repo 內找不到任何呼叫它的程式，實際的退信處理走 IMAP。
- [ ] `App__BaseUrl`：郵件裡的「申請進度查詢」「登入」「重設密碼」連結都用它組（`{BaseUrl}/member/register/status?...`）。**必須是前台公開網址且含站台路徑**（前台 `basePath` 是 `/sps`，所以正式環境若掛在 `/sps` 底下就要寫 `https://主機/sps`）。上線後寄一封測試信點連結確認不會 404（目前本機環境的設定是 `https://sdd.nat.gov.tw/sps`，連結都長 `{BaseUrl}/member/reset-password?token=…`，代表前台掛在 `/sps` 底下）。
- [ ] `CORS_Setting__WithOrigins`：要包含前台與後台的正式網址，且需允許帶 cookie。後台請求新增了自訂標頭 `X-Admin-Client`（後端 CORS 已設 `AllowAnyHeader`，若前面的 nginx／WAF 有自己限制標頭白名單要加）。
- [ ] **前台與 API 必須讓 cookie 通用**（同一個主機名，透過 nginx 分路徑）。申請存取密鑰 cookie `appkey_{id}` 和登入 cookie 一樣由 API 設定，前台完成頁（Server Component）要從收到的請求讀出它再轉傳給 API。若前台與 API 是不同主機名（例如 `www.x.com` 與 `api.x.com`），完成頁會讀不到 cookie 而顯示「找不到申請資料」。登入 cookie 本來就有同樣的前提，所以多半沒問題，但請實測一次完整申請流程。
- [ ] cookie 的 `Secure`／`SameSite` 來自資料庫的「HTTP 安全設定」（系統設定→安全設置），申請存取密鑰 cookie 沿用同一份設定。
- [ ] SMTP：「系統設定→郵件」要是啟用狀態且設定正確。補寄功能會在郵件服務停用時明確回報「沒寄出」。

## F. 之後改程式的規則

### 後端 API 的權限（最容易出事）

1. **後台專用端點一律兩層**：`[Authorize(Roles = "Admin")]`（是不是後台使用者）＋ `[RequirePermission(UserPermission.X)]`（有沒有這項權限）。**不要只寫裸的 `[Authorize]`**：會員 token 也過得去。
2. **後台與會員的權限 claim 名稱不同**：後台 `Permissions`（`UserPermission` 位元）、會員 `MemberPermissions`（`MemberPermission` 位元），常數在 `SPS.Domain/Constants/AuthClaimTypes.cs`。兩個列舉的位元意義互不相干（會員的 `ViewCompany` = bit0 = 後台的 `ManageUsers`），**不要直接 `FindFirst("Permissions")`**：後台用 `User.GetAdminPermissions()`、會員用 `User.GetMemberPermissions()`，兩者都會先確認身分（後台要 Admin 角色；會員要有 MemberId 且沒有 Admin 角色）。新增讀取權限的程式碼一律走這兩個方法。
3. **`[AllowAnonymous]` 擋不住 `IAuthorizationFilter` 型的屬性**（`RequirePermission` 就是）。在同一個 controller 同時有匿名與受保護的 action 時，不要把 `RequirePermission` 放在 class 上，放在各 action（例如 `SystemInfo` 的 `health`、`FileManagement` 的 `download`）。
4. **公開的 GET 列表／詳情要強制只回已發布**：非 Admin 呼叫時覆寫 `Published = true`，詳情對草稿回 404。新增有「發布／上架」狀態的內容類型時照做。
5. **匿名可呼叫的 DTO 不要帶內部欄位**：負責人聯絡資料、備註、營收、窗口名單、審核員備註這類，非 Admin 要清掉（見 `CompanyController.HideInternalFields`）。
6. **匿名端點要有第二因子與限流**：申請編號可以猜，所以進度查詢要信箱／電話、並限制失敗次數；webhook 要有共享密鑰。申請資料的讀寫靠 `appkey_{id}` cookie，不是 GUID。
7. **授權上限**：建立／修改角色、指派角色只能給自己也擁有的權限（`CanGrant`）。新增任何「授予權限」的功能都要套用。
8. **前後台共用的路徑**（`/api/News`、`/api/Banner` 這類）靠 AdminWeb 帶的 `X-Admin-Client` 標頭，讓後端優先採用 `adminAccessToken`。新增後台 API client 時沿用 `lib/api-client.ts` 的 axios 實例。

### 密碼重置與一次性連結

- 重置令牌（JWT）簽發時把「當時密碼雜湊的指紋」（`PwdStamp`，`PasswordStamp.Compute`）寫進去，驗證時與目前密碼雜湊比對（`PasswordStamp.Matches`）：密碼一改（用這個連結重設、或之後自己改）所有舊連結一起失效，不需要另外存「已使用的令牌」。沒有指紋的舊令牌一律視為無效。**之後如果新增其他「寄連結讓人改密碼／登入」的流程，照這個做法，不要只靠效期。**
- 匿名且會「替任意信箱寄信」的端點（忘記密碼、發驗證碼…）一定要有限流與冷卻，不能只靠驗證碼（驗證碼場景可能被關掉）。同信箱冷卻期間也要回成功，不要洩漏這個信箱有沒有註冊。

### 新增或調整權限旗標（`UserPermission`）

- 位元**不可重用、不可改號**（已存在資料庫），**不可超過 bit 52**（API 回傳的 JSON 數字超過 2^53 會失去精度）。
- 新旗標要同步更新四處：`UserPermission.All`、`AdminRoleService.GetAllPermissions`、AdminWeb `lib/permissions.ts`（含 `expandPermissions`）、AdminWeb `AdminLayout.tsx` 的選單權限；並寫 migration 決定現有角色要不要自動補上，否則上線後沒人有這項權限。
- 「維護包含檢視」的規則在後端 `Expand()` 與前端 `expandPermissions()`，改一邊一定要改另一邊。
- 角色權限改動後，使用者要重新登入才生效（權限寫在 token）。

### Migration

- 手寫的 SQL 要用**實際的資料表名稱**（例如是 `UserRole` 不是 `UserRoles`、`Company` 不是 `Companies`），並且**實際跑一次 `Down`**——這次就是靠回滾測試才抓到表名寫錯。
- 純資料的 migration 用 `dotnet ef migrations add` 產生空殼後手寫 `Up`／`Down`，種資料要用 `WHERE NOT EXISTS` 讓重跑安全。
- 因為啟動時自動套用，**新增 migration 的版本一發佈就會改正式資料庫**；有資料轉換的務必先在測試環境用正式資料備份演練。

### 信件

- 信件範本以資料庫為準，程式裡的預設值只在資料庫沒有該範本時才用。**改了預設範本或新增變數，要同步到後台信件範本**。
- `EmailService.SendEmailAsync` 在郵件服務停用時會**靜默略過、不丟例外**。需要確實告知使用者「有沒有寄出」的功能，要先呼叫 `IsEnabledAsync()`。
- 寄信失敗不應該影響主流程的地方（申請提交、審核）已經包 try/catch；補寄這種「寄信就是主要目的」的功能則要把失敗回報給操作者。

### 前台（SPS.Web）

- API 回傳欄位名稱以 `url`／`uri` 結尾且以 `/` 開頭的值，axios 攔截器會自動加上 basePath，搭配 `next/link` 會變成 `/sps/sps/…`。這類欄位要在 `lib/api.server.ts` 用 `stripBasePath` 處理。
- Server Component 呼叫需要瀏覽器 cookie 的 API（例如申請存取密鑰）時，cookie 不會自動帶，要用 `cookies()` 讀出再手動轉傳。
- 計數類 API（瀏覽數、曝光、點擊）用 `fetch(..., { keepalive: true })`，不要用 axios：axios 送 POST 前會先等 CSRF token，遇到整頁跳轉的點擊會在送出前就被中止。
- Banner 沒有設定時各處都是「整塊不顯示」，不要再放回假資料。
- 舊站 CSS 會改掉一些全域元素的外觀：許多頁面的 `<a>` 文字預設是白色（原本放在深色按鈕上）、`.btn-close` 是把「X」文字畫成圓鈕。在白底的元件（例如對話框）裡放連結或關閉鈕時，要自己指定文字顏色、並在關閉鈕裡放 `X` 文字，否則會整行字看不見。
- **靜態檔案（`wwwroot`）**：啟動時 `StaticFileScannerService` 會把 `wwwroot` 底下所有檔案登錄成公開的靜態檔案；同路徑的檔案內容換了（雜湊不同）會更新資料庫的大小與雜湊，已被刪除的紀錄也會恢復。要 seed 內容時，照 `ContributeFormatSeeder` 的做法：掃描完才 seed、用內容雜湊標記「已套用的版本」，不要每次啟動都蓋掉管理員在後台的調整。
- **`ASPNETCORE_WEBROOT` 指到別的目錄時（目前正式機就是）**：部署機的 compose 把 WebRoot 設成掛載進容器的主機目錄（`/home/shareproject/SPS`），而不是映像裡的 `/app/wwwroot`，所以靜態檔案掃描掃的是主機目錄，映像裡的 `wwwroot/seed` 掃不到、seed 就不會套用（現象：下載資源全是「準備中」、投稿頁「投稿格式準備中」，log 也沒有任何 seed 訊息）。`StaticFileScannerService.SyncSeedFiles` 現在會在掃描前，把應用程式內建的 `wwwroot/seed` 複製到實際的 `WebRoot/seed`（只複製缺少或內容不同的檔案）。注意這個目錄會被掃描並公開在檔案管理，**WebRoot 不要指到含原始碼、.env、設定檔的目錄**。
- 檔案管理的「文件」分類（`FileRepository`）要包含 ODF（`.odt／.ods／.odp`），否則後台選檔對話框的「文件」篩選看不到 `.odt`。
